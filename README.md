# Erdős Problem #1220 in Lean 4

A Lean 4 formalization settling [Erdős problem #1220](https://www.erdosproblems.com/1220) in the
sense **"not provable in ZFC"**:

> Let `λ` be a singular cardinal such that both `λ` and `cf(λ)` are `ℵ₀`-inaccessible
> (`μ^ℵ₀ < κ` for all `μ < κ`). Does `λ → (λ, ℵ₁)²` hold?
> — erdosproblems.com/1220 (Erdős–Hajnal 1971, [ErHa71, p.21])

The affirmative statement — every such `λ` satisfies `λ → (λ, ℵ₁)²` — is **not a theorem of ZFC**:
there is a model of ZFC containing a singular `λ` with `λ` and `cf(λ)` `ℵ₀`-inaccessible and
`λ ↛ (λ, ℵ₁)²`. Stated in Mathlib's own first-order logic, with the comparator targets

```lean
theorem erdos1220_not_provable : ¬ (ZFC ⊨ᵇ Erdos1220.FOL.Erdos1220)
theorem erdos1220_sentence_faithful :
    (ZFSet.{0} ⊨ Erdos1220.FOL.Erdos1220) ↔ Erdos1220.Problem1220.{0}
```

`Erdos1220.FOL.Erdos1220` is the first-order sentence expressing the affirmative answer, and
`erdos1220_sentence_faithful` certifies that in Mathlib's `ZFSet` it is equivalent to the
Mathlib-level statement `Erdos1220.Problem1220` of the problem as posed on erdosproblems.com. Both
targets are proved from `propext`, `Classical.choice` and `Quot.sound` only.

**Scope.** The result is non-provability (the answer "yes" cannot be proved in ZFC). The
consistency of the affirmative answer (which holds, e.g., under GCH) and hence full independence
are not part of this formalization.

## Mathematics

The consistency of a negative answer is due to Shelah and Stanley, *A theorem and some consistency
results in partition calculus*, Ann. Pure Appl. Logic 36 (1987) 119–152 (Sh:258), §3. The
formalization follows their historical forcing with these choices:

- **Witness.** The ground-model strong limit `λ = ℶ_{𝔠⁺}` (`Erdos1220/BethWitness.lean`): singular,
  `cf λ = κ = 𝔠⁺`, `λ` and `cf λ` `ℵ₀`-inaccessible — no deep cardinal arithmetic needed.
- **Forcing.** Block-preserving, block-covering histories of basic conditions (blocks are the
  intervals `[ℶ_i, ℶ_{i+1})`, `i < κ`), ordered by weak (flip-closed) extension.
- **Properties.** `μ⁺`-strategic closure, hence `μ`-distributivity (`Erdos1220/WeakOrder.lean`,
  `Erdos1220Full/CoverForcing.lean`); the `(2^μ)⁺`-chain condition in ZFC without GCH
  (`Erdos1220/DeltaSystem.lean`, `Erdos1220/HistoryBlueprint.lean`).
- **In the Boolean-valued model** (regular-open algebra, Flypitch): the hypotheses on `λ` hold
  (`hyp₁`), the generic colouring is a colouring of `[λ]²` (`colouring₁`), it has no red
  homogeneous set of size `λ` (`red₁`, Sh:258 §3.9) and no blue homogeneous set of size `ℵ₁`
  (`blue₁`, §3.7). Flypitch's completeness theorem turns this into a two-valued model of ZFC
  satisfying `¬ Erdos1220` (`Erdos1220Full/Independence1220.lean`).

## How to verify

Toolchain `leanprover/lean4:v4.35.0-rc3`, Mathlib `c55e6e786f49471c72fbddbec5415808896aec1e` (tag `v4.35.0-rc3`).

```sh
lake exe cache get && lake build
python3 sync_challenge.py --check
lake env lean AxiomAudit.lean
bash scripts/install-comparator-tools.sh "$PWD/.tools"   # Linux with Landlock
bash scripts/install-nanoda.sh "$PWD/.tools"
bash scripts/run-comparator.sh "$PWD" "$PWD/.tools" comparator.json
```

**Recorded result (2026-09-26 KST), Lean v4.35.0-rc3.** comparator `777e7f5` and lean4export
`66f1fb4` (tag `v4.35.0-rc3`), both built with the project toolchain; landrun 0.1.15 sandbox;
NanoDa (`robsimmons/nanoda_lib` `68d5ca9`). Verified independently on the released tree (Git pin of
`jbaelaw/flypitch4-lean` @ `78e1fd0`) and on the port tree:

The same checks passed earlier on Lean v4.34.0-rc1 (commit `4f51c83`).

The Challenge's transitive import closure contains only Lean core, Mathlib and Mathlib's pinned
dependencies. The whole library audit (`Erdos1220Full/AxiomAudit.lean`) finds no declaration
depending on anything but the three standard axioms (1831 declarations), and no `sorry`.

**Toolchain history.** The development was first verified on Lean v4.34.0-rc1 (commit 4f51c83,
the toolchain of the erdos501 dependency), then ported to v4.35.0-rc3 (Palomar requires
≥ v4.35.0-rc2). The erdos501 dependency is used through the fork `jbaelaw/flypitch4-lean`
(branch `lean-v4.35.0-rc3`), which is upstream 218d1c1 plus renamed/removed-lemma fixes only.

**Why erdos501?** It is used only as a library: it contains the Lean 4 port of Flypitch
(Boolean-valued models, forcing, completeness theorem) and the Mathlib-ModelTheory definition of
`ZFC` used by its own Palomar challenge. None of its #501-specific results are imported.
